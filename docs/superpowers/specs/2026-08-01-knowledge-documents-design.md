# SchoolWorkHub 문서·지식 모듈 설계

## 1. 목적과 범위

이 문서는 SchoolWorkHub의 첫 업무 편집 모듈인 내부 지식 문서 기능을 정의한다.

이번 범위의 핵심 흐름은 다음과 같다.

`문서 작성 → 자동 복구 초안 → 임시저장 → 필요 시 승인 요청 → 발행 → 열람·검색 → 버전 비교·복원`

이번 범위에 포함한다.

- 내부 지식 문서 작성, 편집, 임시저장, 발행, 열람
- 학교 전체·특정 부서·비공개 공개 범위
- 작성자와 지정 편집자의 공동 편집 권한
- 중요 문서의 선택적 승인·반려·재요청
- 저장 단위 버전 생성과 이전 버전 열람·비교·복원
- 변경 후 5초 유휴 시 자동 복구 초안 저장
- 직접 첨부와 학교 공용 파일 연결
- 제목·본문·태그·부서·작성자·공개 범위·상태 검색
- 휴지통 이동과 30일 이내 복구
- 권한 검증과 감사 로그
- 기존 Electron 보안 경계, 인증서 고정, 오프라인 읽기 전용 정책 유지

이번 범위에서 제외한다.

- 공문 결재 전용 워크플로
- 오프라인 본문 작성·수정·발행
- 첨부파일 본문의 오프라인 캐시
- 실시간 동시 편집
- 외부 공개 링크
- 전자서명과 법적 문서 보존 정책 자동화

## 2. 상태 모델

문서 상태는 다음 값으로 관리한다.

- `draft`: 임시저장된 공식 초안
- `pending_approval`: 중요 문서 승인 대기
- `rejected`: 반려 후 수정 가능
- `published`: 공개 범위 내 사용자에게 발행
- `unpublished`: 발행 취소 상태. 버전은 유지하고 비공개 처리
- `trashed`: 휴지통 이동. 30일 이내 복구 가능
- `purged`: 영구 삭제 완료를 나타내는 감사용 종료 상태. 운영 데이터에서는 제거 가능

자동저장은 공식 상태가 아니다. 사용자별 복구 초안으로 별도 저장하며 공식 버전 이력에 포함하지 않는다.

상태 전이는 다음을 허용한다.

- 신규 문서 → `draft`
- `draft` → `published`
- `draft` → `pending_approval`
- `pending_approval` → `published`
- `pending_approval` → `rejected`
- `rejected` → `draft`
- `rejected` → `pending_approval`
- `published` → `unpublished`
- `draft`, `rejected`, `published`, `unpublished` → `trashed`
- `trashed` → 삭제 직전 상태로 복구
- `trashed` → 보존기간 경과 후 영구 삭제

승인 대기 중에는 작성자와 지정 편집자가 새 초안을 만들 수 있으나, 승인 요청 당시 버전은 변경하지 않는다. 수정 후에는 기존 요청을 취소하고 새 버전으로 다시 승인 요청해야 한다. 승인 대기 문서를 삭제하려면 먼저 승인 요청을 취소해야 한다.

## 3. 공개 범위

작성자는 문서별로 다음 공개 범위를 선택한다.

- `private`: 작성자와 지정 편집자만 열람
- `departments`: 선택한 하나 이상의 부서 구성원에게 공개
- `school`: 같은 학교의 권한 보유 사용자에게 공개

공개 범위는 문서의 현재 설정과 각 공식 버전에 함께 기록한다. 이전 버전 조회 시 당시 공개 범위를 표시한다.

서버는 모든 목록·검색·상세 조회에서 접근 가능한 문서만 반환한다. 클라이언트가 전체 결과를 받은 뒤 숨기는 방식은 사용하지 않는다.

## 4. 권한 모델

역할명이 아니라 권한 코드로 접근을 판단한다.

- `knowledge.read`: 공개 범위에 맞는 문서 열람
- `knowledge.create`: 문서 작성
- `knowledge.edit.own`: 본인이 작성한 문서 수정
- `knowledge.edit.assigned`: 지정 편집자로 등록된 문서 수정
- `knowledge.publish`: 일반 문서 발행과 발행 취소
- `knowledge.approve`: 중요 문서 승인·반려
- `knowledge.delete`: 문서 휴지통 이동
- `knowledge.restore`: 휴지통 문서 복구
- `knowledge.history.read`: 버전 이력 조회와 비교
- `knowledge.history.restore`: 이전 버전 복원
- `knowledge.manage.shared_files`: 학교 공용 파일 연결 관리

작성자와 지정 편집자는 내용 수정, 임시저장, 승인 요청, 일반 문서 발행이 가능하다. 중요 문서는 `knowledge.approve` 권한 보유자의 승인 후에만 발행된다.

서버는 모든 변경 API에서 현재 사용자, 문서 소유권, 지정 편집자 여부, 공개 범위, 상태, 권한 코드를 다시 검증한다.

## 5. 편집기와 문서 형식

본문은 구조화된 JSON과 검색용 정제 텍스트를 함께 저장한다.

구조화 JSON은 다음 요소를 지원한다.

### 기본 서식

- 제목과 소제목
- 일반 문단
- 굵게·기울임·밑줄
- 글머리표·번호 목록
- 표
- 링크
- 이미지
- 인용문

### 업무 블록

- 담당자
- 관련 일정
- 체크리스트
- 참고 문서
- 첨부파일
- 학교 공용 파일 연결

HTML 원문만 저장하지 않는다. 렌더링 시 허용된 노드와 속성만 사용하며 외부 스크립트, 임의 이벤트 속성, 위험한 URL 스킴을 차단한다.

검색용 텍스트는 제목, 본문 텍스트, 체크리스트, 담당자 표시명, 참고 문서 제목을 정규화해 생성한다. 첨부파일 본문 내용은 이번 범위에서 검색하지 않는다.

## 6. 저장과 버전 관리

### 자동저장

- 사용자가 변경한 뒤 5초간 추가 입력이 없으면 저장한다.
- 사용자·문서별 복구 초안 1개만 유지한다.
- 자동저장본은 공식 버전 이력에 포함하지 않는다.
- 성공 시 마지막 자동저장 시각을 화면에 표시한다.
- 네트워크 오류 시 재시도 가능 상태를 표시하며 로컬 본문 캐시는 만들지 않는다.
- 문서가 다른 사용자의 공식 저장으로 변경되면 자동저장본을 즉시 덮어쓰지 않고 충돌 상태로 전환한다.

### 공식 버전 생성

다음 동작에서만 공식 버전을 생성한다.

- 임시저장
- 발행
- 이전 버전 복원

승인 요청은 새 버전을 만들지 않는다. 승인 요청 직전 반드시 최신 변경을 임시저장하고, 승인 요청은 그 공식 버전 ID를 참조한다. 승인자가 승인하면 해당 요청 버전을 발행 상태로 전환하면서 발행 버전을 생성한다.

각 버전은 다음을 기록한다.

- 버전 번호
- 제목
- 구조화 본문
- 검색용 정제 텍스트
- 공개 범위와 대상 부서
- 태그
- 직접 첨부 메타데이터
- 공용 파일 참조와 당시 파일명·버전 정보
- 작성자
- 저장 시각
- 저장 동작 종류
- 변경 사유
- 이전 버전 ID

이전 버전 복원은 기존 이력을 덮어쓰지 않는다. 선택한 버전을 기반으로 새 공식 버전을 생성한다.

### 동시 편집 충돌

문서는 정수형 `revision`을 가진다. 모든 변경 요청은 클라이언트가 알고 있는 `revision`을 함께 전송한다.

- 일치하면 저장하고 `revision`을 증가시킨다.
- 불일치하면 `409 Conflict`와 현재 버전 요약을 반환한다.
- 클라이언트는 내 변경과 서버 최신본을 비교해 병합하거나 새로고침하도록 안내한다.

실시간 공동 편집과 자동 병합은 이번 범위에서 제외한다.

## 7. 승인 흐름

일반 문서는 작성자 또는 지정 편집자가 즉시 발행할 수 있다.

중요 문서는 다음 흐름을 사용한다.

`초안 저장 → 승인 요청 → 승인 또는 반려 → 승인 시 발행`

승인 요청은 저장된 특정 공식 버전을 참조한다. 승인자는 제목, 본문, 공개 범위, 첨부 변경 내역을 확인한다.

반려 시 반려 사유를 필수로 기록한다. 작성자 또는 지정 편집자는 새 버전을 저장한 뒤 다시 승인 요청한다.

승인·반려·요청 취소·재요청은 모두 감사 로그에 기록한다.

## 8. 첨부파일과 공용 파일

### 직접 첨부

- 문서에 종속된다.
- 서버가 허용 확장자, MIME 유형, 파일 크기를 검증한다.
- 업로드 완료 전에는 문서 버전에 포함하지 않는다.
- 문서가 휴지통으로 이동하면 첨부도 삭제 대기 상태로 전환한다.
- 문서 복구 시 첨부도 복구한다.
- 문서 영구 삭제 시 첨부 파일과 메타데이터를 제거한다.

### 학교 공용 파일 연결

- 원본 파일을 복제하지 않고 공용 파일 ID로 참조한다.
- 현재 공용 파일과 문서 버전 작성 당시의 파일명·버전 정보를 함께 표시한다.
- 문서를 삭제해도 공용 파일 원본은 삭제하지 않는다.
- 사용자가 현재 공용 파일에 접근할 권한을 잃으면 문서에는 참조 존재만 표시하고 다운로드는 차단한다.

Electron 렌더러는 파일 시스템이나 서버 업로드 엔드포인트에 직접 접근하지 않는다. 메인 프로세스의 제한된 IPC를 통해 파일 선택, 업로드, 다운로드를 수행한다.

## 9. 검색과 목록

검색 조건은 다음을 지원한다.

- 제목·본문 통합검색
- 태그
- 부서
- 작성자
- 공개 범위
- 문서 상태
- 중요 문서 여부
- 작성일·수정일 범위

기본 정렬은 최근 수정순이다. 사용자는 중요 문서와 자주 보는 문서를 고정할 수 있다.

목록 화면은 다음 구역을 제공한다.

- 전체 문서
- 내 초안
- 내가 편집 가능한 문서
- 승인 대기
- 중요 문서
- 고정 문서
- 휴지통

검색 결과는 서버에서 접근 제어를 적용한 뒤 반환한다. 제목과 최소 메타데이터만 오프라인 캐시에 포함하며 본문과 첨부는 포함하지 않는다.

## 10. 삭제와 복구

삭제는 즉시 영구 삭제하지 않고 휴지통으로 이동한다.

- `deleted_at`과 `purge_after`를 기록한다.
- 기본 `purge_after`는 삭제 시각부터 30일이다.
- 30일 이내에는 권한 보유자가 복구할 수 있다.
- 복구 시 기존 문서 ID, 버전 이력, 첨부 관계를 유지한다.
- 백그라운드 작업이 만료 문서를 영구 삭제한다.
- 별도 보존 잠금이 설정된 문서는 영구 삭제 대상에서 제외한다.

삭제, 복구, 영구 삭제, 보존 잠금은 모두 감사 로그에 기록한다.

## 11. 데이터 모델

핵심 테이블은 다음과 같다.

- `knowledge_documents`
  - 현재 상태, 공개 범위, 중요 여부, 작성자, 현재 버전, revision, 삭제 정보
- `knowledge_document_versions`
  - 공식 버전 스냅샷과 변경 사유
- `knowledge_document_editors`
  - 지정 편집자
- `knowledge_document_departments`
  - 부서 공개 대상
- `knowledge_tags`
  - 학교 단위 태그 사전
- `knowledge_document_tags`
  - 문서와 태그 연결
- `knowledge_attachments`
  - 직접 첨부 메타데이터와 저장 위치
- `knowledge_version_attachments`
  - 공식 버전별 직접 첨부 스냅샷
- `knowledge_shared_file_links`
  - 공용 파일 참조와 당시 파일 버전 정보
- `knowledge_approval_requests`
  - 승인 요청 버전, 상태, 승인자, 사유
- `knowledge_autosave_drafts`
  - 사용자별 복구 초안
- 기존 `audit_logs`
  - 중요 작업 기록

모든 업무 데이터는 `school_id`로 학교를 분리한다. 자동저장 초안은 작성자 또는 현재 편집자에게만 보인다.

## 12. API 경계

주요 API는 다음 책임으로 나눈다.

- 문서 목록·검색
- 문서 생성·상세 조회
- 자동저장 복구 초안 저장·조회·삭제
- 공식 임시저장
- 발행·발행 취소
- 승인 요청·승인·반려·요청 취소
- 편집자·공개 범위·태그 관리
- 직접 첨부 업로드·다운로드·삭제
- 공용 파일 연결·해제
- 버전 목록·상세·비교·복원
- 휴지통 이동·복구

모든 변경 API는 idempotency key 또는 revision 검증을 사용해 중복 요청과 충돌을 통제한다.

API 오류는 사용자 행동 기준으로 구분한다.

- `VALIDATION_FAILED`: 입력 수정 필요
- `FORBIDDEN`: 권한 부족
- `DOCUMENT_CONFLICT`: 최신본 비교 필요
- `APPROVAL_REQUIRED`: 승인 요청 필요
- `APPROVAL_STALE`: 요청 버전이 최신이 아님
- `ATTACHMENT_REJECTED`: 파일 정책 위반
- `DOCUMENT_TRASHED`: 휴지통 문서 변경 시도
- `NETWORK_UNAVAILABLE`: 재시도 가능
- `CERTIFICATE_MISMATCH`: 보안 차단

- 자동저장
- 임시저장
- 발행·승인 요청
- 버전 조회·비교·복원
- 첨부 선택·업로드
- 공개 범위·편집자 설정
- 삭제·복구

토큰, 인증서, 정책 경로, 로컬 파일 시스템 경로를 렌더러에 노출하지 않는다.

### 렌더러

- 문서 목록과 필터
- 편집기
- 자동저장 상태
- 충돌 비교 화면
- 승인 대화상자
- 버전 이력·비교
- 공개 범위·편집자 설정
- 첨부·공용 파일 선택
- 휴지통

## 14. 화면과 UX

### 문서 목록

- 상단 통합검색
- 상태·부서·작성자·공개 범위 필터
- 최근 수정순 기본 정렬
- 중요·고정 표시
- 빠른 새 문서 버튼

### 편집 화면

상단 고정 영역에 다음을 표시한다.

- 문서 상태
- 마지막 자동저장 시각
- 마지막 공식 저장 시각
- 공개 범위
- 중요 문서 여부
- revision 충돌 상태

주요 동작은 다음 세 개로 제한한다.

- 임시저장
- 승인 요청
- 발행

중요 문서는 `발행` 대신 `승인 요청`을 기본 동작으로 표시한다.

### 버전 화면

- 버전 타임라인
- 두 버전 선택 비교
- 제목·본문·업무 블록·첨부·공개 범위 차이 표시
- 복원 사유 입력 후 새 버전 생성

### 휴지통

- 삭제일과 영구 삭제 예정일 표시
- 복구
- 관리 권한 보유자의 즉시 영구 삭제는 이번 범위에서 제공하지 않는다.

## 15. 오프라인과 보안 정책

기존 보안 기준을 유지한다.

- 오프라인에서는 문서 목록과 최소 메타데이터만 조회한다.
- 본문, 이미지, 직접 첨부, 공용 파일 본문은 기본 오프라인 캐시에 저장하지 않는다.
- 오프라인 작성·수정·발행·승인·삭제·복구를 허용하지 않는다.
- 인증서 불일치 시 목록을 포함한 모든 문서 화면을 차단한다.
- 재연결 후 목록·상태·권한만 증분 동기화한다.
- 문서 본문은 서버에서 권한을 재검증한 뒤 매번 조회한다.

## 16. 감사 로그

다음 동작을 감사 로그에 기록한다.

- 문서 생성
- 자동저장 실패와 충돌
- 공식 저장
- 발행·발행 취소
- 승인 요청·승인·반려·취소
- 편집자 변경
- 공개 범위 변경
- 첨부 업로드·삭제
- 공용 파일 연결·해제
- 버전 복원
- 휴지통 이동·복구·영구 삭제
- 권한 거부와 보안 차단

감사 로그에는 비밀번호, 액세스 토큰, 갱신 토큰, 문서 본문 전체, 첨부 파일 원문을 기록하지 않는다.

## 18. 완료 기준

다음 조건을 모두 충족하면 이번 마일스톤을 완료로 판단한다.

- API 데이터 모델과 마이그레이션이 적용된다.
- 문서 생성·편집·임시저장·발행·열람이 실제 서버와 Electron 앱에서 동작한다.
- 작성자와 지정 편집자 권한이 서버에서 검증된다.
- 학교 전체·복수 부서·비공개 공개 범위가 적용된다.
- 중요 문서 승인·반려·재요청이 동작한다.
- 자동저장과 공식 버전 이력이 분리된다.
- 버전 열람·비교·복원이 새 버전 생성 방식으로 동작한다.
- 직접 첨부와 공용 파일 연결이 동작한다.
- 제목·본문·태그·필터 검색이 동작한다.
- revision 기반 충돌 차단이 동작한다.
- 휴지통 이동과 30일 이내 복구가 동작한다.
- 오프라인에서는 목록만 읽기 전용으로 보이고 변경 기능이 잠긴다.
- 인증서 불일치 시 문서 화면 전체가 보안 차단된다.
- 감사 로그에 중요 작업이 기록되고 민감정보는 기록되지 않는다.
- API CI, Teacher Client Ubuntu CI, Windows 네이티브 CI가 모두 통과한다.
